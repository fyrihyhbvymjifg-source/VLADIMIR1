FORBES — КОНТРАКТ ДЛЯ ИГРОВЫХ РАЗРАБОТЧИКОВ

1. ИСТОЧНИК ИСТИНЫ
Презентационная сборка не имеет доступа к базе проекта и игровому клиенту.
Не выдавайте реальный допуск по числам из браузера или localStorage.
Сервер определяет персонажа из аутентифицированной игровой сессии, проверяет
доступ к выбранному serverId и рассчитывает капитал на собственных данных.
Общая стоимость считается в целых игровых рублях, без floating-point денег.

Для имущества нужны уникальный assetId, тип, владелец, доля владения,
оценочная стоимость из каталога сервера и версия каталога. Один объект нельзя
учитывать в нескольких категориях. Кошелёк бизнеса нельзя прибавлять к банку,
если он уже входит в стоимость бизнеса. Обязательства вычитаются однократно.
Межсерверный перевод капитала или объединение персонажей не предполагается.

2. ПОДКЛЮЧЕНИЕ КЛИЕНТА
Настройте club-config.js: mode: 'live', apiBase: '/api/forbes'.
API должен быть на том же origin; запросы используют cookies игровой сессии.
На стороне сервера нужны проверка Origin/CSRF, авторизация каждого действия,
контроль доступа к персонажу и rate limit. Никаких секретов в JavaScript.
Ни один клиентский переключатель или demo-черновик не подтверждает членство.
В live-режиме сохранённые демо-черновики не читаются.

3. GET /api/forbes/profile?serverId=78
Возвращает актуальный снимок персонажа из сессии:
{
  "serverId": 78,
  "nick": "Player_Name",
  "checkedAt": "2026-10-14T19:00:00Z",
  "minimum": 350000000,
  "assets": {
    "cash": 55000000,
    "bank": 95000000,
    "business": 180000000,
    "property": 40000000,
    "vehicles": 45000000,
    "other": 5000000,
    "debts": 0
  }
}
Все семь сумм обязательны, неотрицательны и целочисленны.
Если порог не задан, minimum: null. Не заменяйте отсутствие данных нулями:
верните ошибку или статус ручной проверки по согласованному расширению API.
401 означает, что требуется вход. При сетевой ошибке клиент не имитирует успех.

4. POST /api/forbes/admission
Тело: { "serverId": 78 }
Клиент не передаёт сумму активов для решения о допуске.
Сервер повторно получает профиль, проверяет полноту и свежесть данных,
рассчитывает капитал, применяет свой порог и сохраняет допуск атомарно.
Ответ:
{
  "status": "member",
  "tier": "MEMBER",
  "profile": { ...полный снимок из пункта 3... }
}
Разрешены status: member, ineligible, review.
Для member tier: MEMBER / VIP / ELITE / LEGEND.
Для ineligible/review tier не нужен.
review — требуется ручная проверка, включая неизвестный порог.
Ровно порог означает допуск. Недостаток капитала не становится автоматическим
отказом в ручной оценке: ошибочную оценку имущества можно оспорить заявкой.
Запрос повторной проверки должен быть безопасен при повторении.

5. POST /api/forbes/applications
Пример тела:
{
  "nick": "Player_Name", "serverId": 78, "capital": 420000000,
  "vk": "https://vk.com/example", "reason": "Нужно учесть новый бизнес",
  "evidence": "https://example.com/evidence", "consent": true, "demo": false
}
nick, capital и evidence — заявления игрока, а не доказанные данные.
Сервер заново валидирует поля, связывает заявку с персонажем из сессии и
проверяет права. Повторную открытую заявку того же персонажа и сервера
следует возвращать с прежним ID, не создавая дубликат.
Ответ подтверждённого приёма: { "id": "F78-000123", "status": "pending" }.
Клиент показывает «на рассмотрении» только после такого ответа.
Переходы модерации: pending → approved / rejected / needs_info.
Причина решения, проверяющий, время, исходные сведения и итоговая оценка
должны фиксироваться на сервере. Модераторская панель в эту сборку не входит.
Отдельные уведомления и запрос статуса после перезагрузки — задача интеграции.

6. РЕЙТИНГ И ПЕРЕСЧЁТ
В этой сборке сохранены 29 исходных участников; заявка и демо-допуск не меняют
их порядок и суммы. Для продакшена замените order в tablet.js данными сервера
с согласованным API рейтинга. Готового рейтингового endpoint в сборке нет.
Игровой сервис должен обновлять данные по событиям покупки/продажи, смены
владельца, банковских операций и изменения каталога цен, а также периодически.
Перед выдачей допуска всегда нужен актуальный снимок; окончательное решение
выдаётся сервером и проверяется сервером при доступе к функциям клуба.
Правила сохранения статуса после падения капитала согласуются администрацией.
Предложение: краткое окно перепроверки и ручное рассмотрение спорных оценок.

7. КРИТЕРИИ ПРИЁМКИ
349 999 999 ₽ на сервере 78 → не хватает 1 ₽.
350 000 000 ₽ → MEMBER.
700 000 000 ₽ → VIP; 1 750 000 000 ₽ → ELITE; 3 500 000 000 ₽ → LEGEND.
420 млн активов − 100 млн обязательств → 320 млн; не хватает 30 млн.
Неизвестный порог → только ручная проверка, независимо от суммы.
Данные другого сервера, ошибки API, неполные активы → допуска нет.
Переход в VK не должен называться отправленной заявкой.
В демо после сохранения явно написано, что администрации ничего не отправлено.
Для живого запуска дополнительно проверьте авторизацию, защиту от подмены
активов, отсутствие дублей заявок, параллельные игровые операции и права
модераторов. Это серверные проверки, не реализуемые статической веб-страницей.
